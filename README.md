# 智能仓储系统 · Intelligent Warehouse System

把厂家清单变成可追溯的现场库存：清单入库、线上出库、固定模板生成出库单、设计量/到货量/剩余量/备品自动核算，再到自动盘库和流水追溯，一套系统覆盖从入库到出库的完整流程。

智能仓储系统面向海外新能源 EPC 项目打造。它保留厂家表格的真实层级，把“标段 → 批次 → 箱号 → 箱内物资”清楚展开；库管按物资搜索并填写数量即可完成批量出库，系统自动拆分来源批次和库位，出库单固定格式生成、可打印、可追溯。不同项目、设备、批次和库位可以按实际管理要求灵活分类录入，减少重复填写和人为错算。

这是一套让项目经理看得懂、库管用得快、账面经得起核对的轻量仓储工具：领导打开先看项目总览，库管进入入库/出库办理，盘库人员按位置核对实物，任何数量变化都落到明确单据和流水上。界面支持中文和英文，先用单机把流程跑顺，再扩展多人协作。

核心能力：

- 厂家 Excel 清单自动识别，兼容工作表、表头、合并单元格、箱号、备注和箱内子项。
- 按固定标段查看设计量、到货率、剩余率和备品，自动发现账面异常。
- 入库、出库、移库、状态调整、备品移交形成统一流水总账，支持自动盘库核对。
- 线上批量出库，自动按多个批次和库位拆分，并按固定模板生成出库单。
- 误录单据可由管理员密码保护删除并回滚库存，普通更正保留作废/冲销痕迹。

## 启动

安装 Python 3.11 或更高版本后，运行 `pip install -r requirements.txt`，再双击 `启动系统.cmd`，浏览器访问 http://127.0.0.1:8765 。本机模式只监听回环地址。

## 公开发布

本仓库是单机试用版，数据库和原始厂家文件不会随代码发布。功能边界和发布说明见 [`宣传文案.md`](宣传文案.md) 与 [`CHANGELOG.md`](CHANGELOG.md)。

## 使用

1. 入库页上传厂家的 .xlsx / .csv 到货清单。装箱清单按箱内详件办理入库；发货清单只作为箱级物流信息，不能直接当作入库明细。系统自动识别表头、合并单元格和重复分页，确认预览后一次性入账；当前不提供资料归档和文件夹自动处理，原始文件仅作为单据溯源依据保留。入库前必须从固定的A1-A16标段下拉选项中选择一个标段，封面合同号不会覆盖该选择。
2. 入库时标段只需选择一次；业务单号可以留空，系统会使用自动生成的入库单号。到货日期默认当天并单独保存，批次序号默认 `1`，到货批次使用简短的 `B01`、`B02` 形式，不包含设备类型和日期。厂家表没有到货批次、仓库和库位列时，系统按整张表套用本次批次、`主仓库` 和 `待分配`，不用逐行补填；管理员仍可在确认前修改。相同单号或相同内容不允许重复过账。表格内可指定不同库位和质量状态。
3. 出库页先按物资汇总显示所有可用库存，可搜索、按A1-A16标段筛选。直接填写“本次数量”就会自动加入待出库清单，也可以勾选多项；最后点击一次确认才真正扣库存。系统自动从多个到货批次和库位拆分，出库单保留每一项的批次、箱号和库位来源；库管不需要逐个位置点击。相近物资按编码、规格和属性分别列出，不会按名称混合。入库批次和箱号只作为来源追溯，不需要在出库时重新填写。
4. 单据查询可打印或在浏览器打印中保存为 PDF，补打不会扣库。普通更正填写原因后走“作废/冲销”，原单和反向单据都会保留；若冲销会造成负库存则阻止。整张误录单据另有“管理员删除（需密码）”，删除前填写密码、原因和管理员姓名，系统回滚库存并留下管理员操作记录；已被后续流水使用的单据、设计基准单和冲销单不能硬删除。
5. “删除办理”是独立入口，按出库页面的方式筛选、勾选一张或多张整单后，一次输入管理员密码、原因和姓名提交。删除只针对整张误录单据；删除后没有设计量、库存或其他单据引用的孤立物资档案也会清理，仍被其他批次或设计基准使用的物资档案会保留。
6. 项目总览按固定A1-A16标段集中显示设计总量、到货率、剩余率和备品；设计总量未设置时显示待设定，不猜测百分比。仓库明细再按“标段 → 到货批次 → 箱号 → 箱内物资”逐层显示，标段、批次和箱号均可展开或收起，并提供“全部展开 / 全部收起”。关键词、标段、批次、仓库、状态可筛选，并可按标段、批次、箱号、物资或数量排序。数量按各自单位显示；库存叶子行同时显示累计入库总量和当前剩余可用量。项目总览和流水总账显示服务端账面核对结果，发现流水与库存位置不一致或入库超过已知设计量时列出异常，不自动修改。箱内某一项的备注若包含“一行一项 + 数量/单位”，会解析成该箱该项的子项明细；子项用于查询和核对，不重复增加库存。原始备注仍可展开查看。平面物资台账和库位表收在“辅助明细”中，需要时再打开。设计量首次导入后锁定和独立设计变更仍在总览中管理；不做未经确认的套件折算。厂家更细清单按实际明细建账，用A1-A16标段关联。厂家未提供物资编码时，系统按本次到货批次生成 `B01-001` 形式的内部可追溯编号；如果后续批次的名称、规格、单位、标段和属性完全相同，则沿用既有内部编码，跨批次查询时不会把同一物资拆开，并在确认前提示管理员核对。
7. 总览中发运批次状态下拉只更新物流状态，不更新数量。待检/隔离/备品通过库存状态调整记录管理，状态调整支持部分数量。只有可用库存可普通出库，备品只能使用备品移交业务。

## 边界

- 当前是单机经办模式，经办人是人工填写的审计字段，不是经过认证的用户身份。管理员删除有本机密码保护，但还没有互联网登录、认证用户和多人角色权限；这些需要下一阶段实现，不应将当前端口公开。首次使用管理员删除前，在“单据查询”设置管理员密码；修改密码需要旧密码。
- 网络版可复用业务服务与集中数据库结构，需补充身份认证、HTTPS、角色及附件授权，评估迁移 PostgreSQL。当前 SQLite 使用事务、唯一键和写入锁控制并发。
- 导出提供 UTF-8 CSV 和可打印单据，PDF 由浏览器“另存为 PDF”生成。
- 不直接执行 Excel 公式；公式单元格需要转换为值，避免过期缓存产生错误库存。旧 .xls 请另存为 .xlsx。
- 多页表头和页脚签字区只做识别预览；合同/标段和箱号列允许合并单元格，下面的明细行自动继承；数量不是数字的版式行会自动忽略并提示。厂家一行中包含多项辅料的长文本会原样留存，后续可再拆分为独立物料。厂家“箱号/箱件号”作为独立箱级追溯信息，不自动冒充到货批次；入库时由管理员从A1-A16选择标段并填写本次到货批次序号。
- 同一物资、同一到货批次、同一箱号、同一仓库和库位重复出现时自动合计数量；不同箱号分别保留。只有名称、规格或单位冲突时才阻止确认。
- 数量最多支持六位小数。不同单位不合计为一个总数量。编号应保存为文本，避免 Excel 丢失前导零。
- 数据保存在 `data/materials.db`，原始导入文件保存在 `data/sources/`。界面提供含数据库和原件的备份下载，恢复前先停服务并保留现有目录副本。
- 空库启动，不混入演示站测试数据。测试使用独立临时数据库。

## 验收重点

验证重复导入、分批入库、多库位、待检阻止出库、备品移交、并发超额发料、事务回滚、独立设计变更、冲销、密码保护的管理员删除及补打不重复扣库；浏览器验证九个入口、单据操作入口、流水筛选和中英文切换。
