# 智能仓储系统 · Intelligent Warehouse System

把厂家清单变成可追溯的现场库存：清单入库、线上出库、固定模板生成出库单、设计量/到货量/剩余量/备品自动核算，再到自动盘库和流水追溯，一套系统覆盖从入库到出库的完整流程。

智能仓储系统面向海外新能源 EPC 项目打造。它保留厂家表格的真实层级，把“标段 → 批次 → 箱号 → 箱内物资”清楚展开；库管按物资搜索并填写数量即可完成批量出库，系统自动拆分来源批次和库位，出库单固定格式生成、可打印、可追溯。不同项目、设备、批次和库位可以按实际管理要求灵活分类录入，减少重复填写和人为错算。

这是一套让项目经理看得懂、库管用得快、账面经得起核对的轻量仓储工具：领导打开先看项目总览，库管进入入库/出库办理，盘库人员按位置核对实物，任何数量变化都落到明确单据和流水上。界面支持中文和英文，先用单机把流程跑顺，再扩展多人协作。

核心能力：

- 厂家 Excel 清单自动识别，兼容工作表、表头、合并单元格、箱号、备注和箱内子项。
- 识别结果按识别时间自动归档；可用日期、类别、标段、批次和状态查找原件与快照。入库预览支持本地 Univer 只读表格核对，无法加载时可分页查看全部 HTML 明细。
- 按固定标段查看设计量、到货率、剩余率和备品，自动发现账面异常。
- 入库、出库、移库、状态调整、备品移交形成统一流水总账，支持自动盘库核对。
- 线上批量出库，自动按多个批次和库位拆分，并按固定模板生成出库单。
- 误录单据可由管理员密码保护删除并回滚库存，普通更正保留作废/冲销痕迹。
- 识别归档支持多选批量删除，并提供“删除记录”和“删除入库单”：前者只清理归档，后者回退库存；仅需删除密码，删除留有审计记录。

### 日常办理（0.1.36）

- 入库：上传或粘贴到货资料，系统建议类型；人工核对、排除不要的行，再确认入库。识别不对时展开“修改资料类型 / 表头”。
- 库存：默认物资列表，也可按箱查看。点“详情”查看原件和收发、移库记录；点“加入发料”选择实际箱号和货位。
- 出库：选择物资数量自动分配，或沿用已选实际货位。填写经办人、接收单位和用途后确认，确认前不扣库存。
- 出库备注：在每行“本次备注”填写说明，生成的单据及打印页显示“备注”列。整单说明填写在“用途 / 安装区域 / 原因”。数量箭头每次按 1 增减，小数可手动输入。
- 入库历史在入库页面上方；备品、流水、移库、状态调整及删除在“更多业务”中。

## 启动

最新版安装包与便携 ZIP：从 [GitHub Releases](https://github.com/1195747769-ai/intelligent-warehouse-system/releases/latest) 下载。仓储核心约48MB，本地AI为独立选装包。

本次 v0.1.36 Release 提供仓储核心安装包、便携包与使用说明；4B模型包未上传，已有本地AI包可继续使用。

Windows 10/11 x64：双击 Setup 安装包；便携 ZIP 请完整解压后双击 `安装.bat`。核心程序自带 Python 和 Excel 读取组件，断网也可安装，不需要另外安装 Python、Node 或 pip。

**双击桌面图标即可**：自动检查环境、启动服务并打开浏览器，直达 http://127.0.0.1:8765；日常启动不再弹出黑色命令窗口。便携目录可双击 `启动系统.cmd`。
如果服务已经在运行，再次双击只会重新打开浏览器，不会重复启动；如果旧服务已经失效，启动器会以端口真实监听状态判断并自动补起，不需要手工选择“重启”。

如果浏览器打开得比服务快，页面会自动重试连接约 1 分钟，服务恢复后自动回到页面；不需要关闭浏览器或重启系统。

需要停止、重启、查看运行状态、看日志或备份数据时，双击 `一键启动控制器.cmd` 打开控制台菜单。

首次启动会自动完成三件事：

1. 检查随包运行环境和表格组件；
2. 在当前安装目录创建独立本地账库（安装包不带个人库存）；
3. 启动服务并打开浏览器，访问 http://127.0.0.1:8765 。

启动器也能脱离窗口独立运行：服务以独立进程启动，关掉控制台窗口不影响系统运行；需要停止时重新打开控制器选择「停止系统」。

### 升级、卸载与可选 AI

- 升级：再次运行新版 Setup，使用原安装目录。库存、单据、备份和本地模型保留，原程序文件备份到 `backups/app-upgrade-*`。
- 卸载：从 Windows“已安装的应用”卸载。数据保留在原目录，重新安装同一目录可继续使用。请勿直接删除整个程序目录。
- 4B AI：先安装核心，把 `InstallAI.cmd` 与 `IntelligentWarehouse-AI-4B-Optional.zip` 放在同一文件夹，双击前者。包约 2.5GB，建议 16GB 内存；无独立显卡时使用 CPU，速度以实际电脑为准。
- 如使用 AI 分包，文件分为 `IntelligentWarehouse-AI-4B-Optional.zip.part01` 和 `.part02`。两段与 `InstallAI.cmd`、`JoinAI.py` 下载到同一文件夹后，双击 `InstallAI.cmd` 自动合并、校验和安装。下载、合并与安装合计建议至少8GB可用空间。
- AI 包需要微软 Visual C++ x64 运行库。缺失时安装入口会给出 [微软官方下载](https://aka.ms/vc14/vc_redist.x64.exe)，不会覆盖原模型。核心入库无需 AI 或这项额外安装。
- AI 只提出名称、规格等识别建议，仍由人工核对确认。草稿可跨业务切页、系统刷新和语言切换保留；关闭浏览器或原生 F5 不保留草稿。

### 命令行方式

不想用菜单时，也可以直接调用控制器脚本（同样会自动处理环境）：

```bat
python launcher.py start      :: 启动并打开浏览器
python launcher.py stop       :: 停止服务
python launcher.py restart    :: 重启
python launcher.py status     :: 查看运行状态
python launcher.py doctor     :: 环境自检（Python / 依赖 / 端口）
python launcher.py backup     :: 备份 data 目录到 backups/
```

端口默认 8765，可用 `--port` 指定；`--no-browser` 表示启动后不自动打开浏览器。

### 手动方式（不推荐）

安装 Python 3.11 或更高版本后，运行 `pip install -r requirements.txt`，再执行 `python server.py`。本机模式只监听回环地址。

### 排障

- 双击后一闪而过或提示找不到 Python：用控制器的「环境自检」查看具体是哪一环缺失，它会逐项列出解释器、依赖和端口状态。
- 本机 `py` 启动器可能指向不存在的路径，控制器已自动绕过，无需修复。
- 运行日志在 `.run/server.log`，控制台菜单里可以直接查看。

## 使用

1. 入库页上传厂家的 .xlsx / .csv 到货清单。装箱清单按箱内详件办理入库；发货清单只作为箱级物流信息，不能直接当作入库明细。系统自动识别表头、合并单元格和重复分页；识别完成后自动保存原件和识别快照，可在“识别归档”按南非当地日期、类别、标段、批次和状态查找。只有确认后才生成入库单并更新库存，单纯识别或取消不会改变库存。入库前必须从固定的A1-A16标段下拉选项中选择一个标段，封面合同号不会覆盖该选择。
2. 入库时标段只需选择一次；业务单号可以留空，系统会使用自动生成的入库单号。到货日期默认当天并单独保存，批次序号默认 `1`，到货批次使用简短的 `B01`、`B02` 形式，不包含设备类型和日期。厂家表没有到货批次、仓库和库位列时，系统按整张表套用本次批次、`主仓库` 和 `待分配`，不用逐行补填；管理员仍可在确认前修改。相同单号或相同内容不允许重复过账。表格内可指定不同库位和质量状态。
3. 出库页先按物资汇总显示所有可用库存，可搜索、按A1-A16标段筛选。直接填写“本次数量”就会自动加入待出库清单，也可以勾选多项；最后点击一次确认才真正扣库存。系统自动从多个到货批次和库位拆分，出库单保留每一项的批次、箱号和库位来源；库管不需要逐个位置点击。相近物资按编码、规格和属性分别列出，不会按名称混合。入库批次和箱号只作为来源追溯，不需要在出库时重新填写。
4. 单据查询可打印或在浏览器打印中保存为 PDF，补打不会扣库。普通更正填写原因后走“作废/冲销”，原单和反向单据都会保留；若冲销会造成负库存则阻止。整张误录单据另有“管理员删除（需密码）”，删除前输入密码，无需管理员账号或姓名，系统回滚库存并留下管理员操作记录；已被后续流水使用的单据、设计基准单和冲销单不能硬删除。
5. “删除办理”是独立入口，按出库页面的方式筛选、勾选一张或多张整单后，一次输入删除密码提交。删除只针对整张误录单据；删除后没有设计量、库存或其他单据引用的孤立物资档案也会清理，仍被其他批次或设计基准使用的物资档案会保留。
6. 项目总览按固定A1-A16标段集中显示设计总量、到货率、剩余率和备品；设计总量未设置时显示待设定，不猜测百分比。仓库明细再按“标段 → 到货批次 → 箱号 → 箱内物资”逐层显示，标段、批次和箱号均可展开或收起，并提供“全部展开 / 全部收起”。关键词、标段、批次、仓库、状态可筛选，并可按标段、批次、箱号、物资或数量排序。数量按各自单位显示；库存叶子行同时显示累计入库总量和当前剩余可用量。项目总览和流水总账显示服务端账面核对结果，发现流水与库存位置不一致或入库超过已知设计量时列出异常，不自动修改。流水总账默认只显示最近 300 条，需要更早的记录时点「加载更早的 300 条」；搜索框和类型筛选在全部流水范围内查询。箱内某一项的备注若包含“一行一项 + 数量/单位”，会解析成该箱该项的子项明细；子项用于查询和核对，不重复增加库存。原始备注仍可展开查看。平面物资台账和库位表收在“辅助明细”中，需要时再打开。设计量首次导入后锁定和独立设计变更仍在总览中管理；不做未经确认的套件折算。厂家更细清单按实际明细建账，用A1-A16标段关联。厂家未提供物资编码时，系统按本次到货批次生成 `B01-001` 形式的内部可追溯编号；如果后续批次的名称、规格、单位、标段和属性完全相同，则沿用既有内部编码，跨批次查询时不会把同一物资拆开，并在确认前提示管理员核对。
7. 总览中发运批次状态下拉只更新物流状态，不更新数量。待检/隔离/备品通过库存状态调整记录管理，状态调整支持部分数量。只有可用库存可普通出库，备品只能使用备品移交业务。

## 大数据量

系统按“物资种类”和“流水条数”两个维度增长。0.1.3 起，刷新页面的耗时不随流水条数增长；0.1.5 起，物资清单也不再全量下发：

| 规模 | 单次刷新耗时 | 页面体积 |
| --- | --- | --- |
| 1,000 种物资 / 20,000 行明细 | 0.22 s | 0.95 MB |
| 5,000 种物资 / 100,000 行明细 | 1.9 s | 3.8 MB |
| 10,000 种物资 / 200,000 行明细 | 4.1 s | 7.4 MB |

（临时库造数实测，不代表真实业务数据。0.1.2 及更早版本在 5,000 种物资时需要 5 分钟以上；0.1.4 的体积约为现在的一倍，因为物资行被重复传了两遍。）

为了做到这一点：

- `lines` / `movements` / `changes` 上补了 5 个业务索引，老数据库首次启动时自动补齐，不需要手工处理。
- 项目总览的逐物资汇总改为批量聚合，不再对每种物资单独查询。
- **流水总账默认只加载最近 300 条**，页面顶部显示「流水共 N 条，默认显示最近 300 条」，点「加载更早的 300 条」继续往前翻。
- **物资总表和物资台账默认只加载前 300 条**，显示「物资共 N 条，默认显示前 300 条」，点「加载后续 300 条」继续翻页。
- **标段不再内嵌一份物资行**，只带物资编码和数量；打开某个标段时才按需取该标段的物资。
- 流水和物资的搜索框**都由服务端在全部范围内查询**，不只是页面上已经加载的部分；输入后约 0.3 秒自动查询。
  这一点是必须的：页面只持有一页数据，在浏览器里筛选会漏掉所有还没翻到的匹配项。
- 「物资种类 / 有库存物资 / 未到货物资」等计数由服务端计算，不加载全量也能显示正确数字。

也就是说：物资种类再多，打开页面都是几秒钟；流水和物资再多，也只在你主动往前翻的时候才传输。

## 边界

- 当前是单机经办模式，经办人是人工填写的审计字段，不是经过认证的用户身份。管理员删除有本机密码保护，但还没有互联网登录、认证用户和多人角色权限；这些需要下一阶段实现，不应将当前端口公开。首次使用管理员删除前，在“单据查询”设置管理员密码；修改密码需要旧密码。
- 网络版可复用业务服务与集中数据库结构，需补充身份认证、HTTPS、角色及附件授权，评估迁移 PostgreSQL。当前 SQLite 使用事务、唯一键和写入锁控制并发。
- 导出提供 UTF-8 CSV 和可打印单据，PDF 由浏览器“另存为 PDF”生成。
- 不直接执行 Excel 公式；公式单元格需要转换为值，避免过期缓存产生错误库存。旧 .xls 请另存为 .xlsx。
- 多页表头和页脚签字区只做识别预览；合同/标段和箱号列允许合并单元格，下面的明细行自动继承；数量不是数字的版式行会自动忽略并提示。厂家一行中包含多项辅料的长文本会原样留存，后续可再拆分为独立物料。厂家“箱号/箱件号”作为独立箱级追溯信息，不自动冒充到货批次；入库时由管理员从A1-A16选择标段并填写本次到货批次序号。
- 同一物资、同一到货批次、同一箱号、同一仓库和库位重复出现时自动合计数量；不同箱号分别保留。只有名称、规格或单位冲突时才阻止确认。
- 数量最多支持六位小数。不同单位不合计为一个总数量。编号应保存为文本，避免 Excel 丢失前导零。
- 数据保存在 `data/materials.db`，原始导入文件保存在 `data/sources/`。界面提供含数据库和原件的备份下载，恢复前先停服务并保留现有目录副本。
- 空库启动，不混入演示站测试数据。测试使用独立临时数据库。

## 验收重点

验证重复导入、分批入库、多库位、待检阻止出库、备品移交、并发超额发料、事务回滚、独立设计变更、冲销、密码保护的管理员删除及补打不重复扣库；浏览器验证九个入口、单据操作入口、流水筛选和中英文切换。

两个 `check_ui_*.js` 用本机 Chrome 的调试协议驱动真实浏览器，不依赖任何 npm 包、也不下载 Chromium，

必须能命中。如果哪天搜索退回成在浏览器里筛已加载的行，这条会红，而纯接口测试完全看不到。
# 到货单与装箱单

入库办理只需两步：放入资料并识别，然后核对勾选物资并确认入库。支持 `.xls/.xlsx/.csv`、粘贴内容和手动填写；手动填写只需箱号、名称、数量、单位，编码和图号收在选填项。每行可移除或恢复。修改后点“核对并确认入库”，系统先重新验证，通过后只入库勾选的物资；有问题会停下并显示原因。列映射在高级设置中，到货单可单独使用，也可与装箱单核对。

可下载简易到货单与装箱单模板，厂家不使用模板也可照常提交原单据。提供虚构的演示工作簿和“演示模式.cmd”；演示模式使用独立的 `demo-data` 数据库、端口 8766，与正式库存分开。演示工作簿中有一处故意设置的数量差异，实际业务不得使用。

原文件下载：单个上传文件保留原始格式与文件名；多个不同文件下载为 ZIP；粘贴或手动录入的来源下载为 Excel。内部识别 JSON 保存在系统中，不作为原文件下载。

## 轻量本地AI辅助识别

入库预览中点击“本地AI辅助识别”，一次最多核对32条明细，优先处理问题行和含规格型号的行。建议显示在物资行下方，选择“采用本行AI建议”后可继续修改，最终仍需确认入库。无法从原文确认的型号、数量或单位不补猜，已有人工修正和完整规格优先保留。复杂表头仍需对照原表手动指定，不保证AI能识别。

本机使用 Qwen3-4B Q4_K_M（2,497,280,480字节）、Qwen官方对话模板和 llama.cpp Vulkan运行程序，自动使用可用显卡；显卡启动失败时回退CPU，保存于安装目录的 `local-ai`。资料仅发送到本机临时模型进程；完成或超时后进程退出，不调用云端AI服务。无需额外Python包或Ollama平台。下载来源与摘要保存于 `local-ai/installation.json`，模型许可在 `local-ai/MODEL-LICENSE.txt`。分发包不包含旧0.6B模型。
